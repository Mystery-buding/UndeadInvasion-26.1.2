## 天数改为真正的「独立计数」（用户纠正）

- 用户定义：独立天数 = 不受 `/time set`、`/time add` 或其它 mod 改写原版时间影响；昼夜外观仍跟随原版时钟
- 废弃 `util/WorldDay`（原实现直接读 overworld 时钟，`/time set` 会改天数），已删除
- 新增 `world/DayCounterData extends SavedData`：字段 `day` / `ticks_into_day` / `last_game_time`，存于主世界 `data/undeadinvasion/day_counter.dat`
  - 推进源是 `Level#getGameTime()`（每 tick +1，时间指令不动它），每 24000 刻 +1 天
  - `last_game_time < 0` 视为首次装载，用世界年龄推算初始天数（兼容旧存档）
  - delta < 0（存档回滚）时重新对齐，避免计数永久停滞
  - 睡觉 `onSleep()`：+1 天且 `ticks_into_day = 0`，对齐清晨
- 新增 `event/DayCounterEvents`：`ServerTickEvent.Post` 推进、`SleepFinishedTimeEvent` 结算、`PlayerLoggedInEvent` 首发
- 新增 `network/DaySyncPayload` + `NetworkSetup`：服务端权威值 `playToClient` 下发；发送前用 `player.connection.hasChannel(TYPE)` 过滤原版客户端
- 新增 `client/ClientDayCounter`：客户端快照，`DayCounterLayer` 只读它，不再自行推算
- 26.x API 备忘：`Entity#getServer()` 已移除，改用 `player.level().getServer()`；`SavedDataStorage#computeIfAbsent(SavedDataType)`；`SleepFinishedTimeEvent` 在 `net.neoforged.neoforge.event.level`
- 设计取舍：按 24000 刻/天推进（等同原版日长）；若以后接入改日长的模组需要另做适配

## 已删除：持矛自动生成马（用户未要求）

- 曾把「拿矛自动乘骑相对坐骑」误解为“持矛就生成僵尸马/骷髅马”，属擅自加需求，已整段删除（含 `mountHorse`、`allowHorseSpawn`）

- **骑手主动找坐骑**（用户要求）：`MountSeekGoal`（无 Flag，priority 0，`undeadinvasion:mount_seek_ai` tag 只挂一次）挂在所有载体上，每 100 tick（5 秒）调 `MobMounts.tryAutoMount` 扫 16 格；僵尸→僵尸马、骷髅→骷髅马、溺尸→僵尸鹦鹉螺、尸壳/焦骸→骆驼尸壳。坐骑入场时还会 `tryFillMount` 立即拉一次人（双向兜底）
- **骆驼乘客阵亡补位**：`LivingDeathEvent` 中只要死者骑的是 `CamelHusk`，就让位 → 剩余乘客按新座位重同步（前排矛/后排弓）→ `tryFillCamel` 补空座（尸壳死则焦骸顶前排，焦骸死则补新焦骸到后排）
- 保留：骑乘后的武器规则（前座/骑手→矛，后座→弓），这条是用户明确要求的

## 长矛自动上坐骑（含骆驼分工）

- `MobMounts.tryAutoMount` 分流（生成时 + 跨天重刷）：
  - **尸壳**：16 格内找骆驼——优先空骆驼（坐前座→换矛）；其次「只有一只焦骸」的骆驼：焦骸 `stopRiding` 让位 → 尸壳坐前座 → 焦骸回后座，两人重新 `sync` 成矛/弓。找不到就步行，不生成骆驼；也不参与 5% 随机马匹
  - **焦骸**：只找骆驼——空骆驼坐前座（换矛），有尸壳的骆驼坐后座（换弓）；找不到就步行，**不骑骷髅马**；同样不参与 5% 随机坐骑（`mountTypeFor` 对 Parched 返回 null）
  - 其它持矛亡灵 → 僵尸马/骷髅马
- `tryCamel(level, rider, day, frontOnly)`：`frontOnly=true` 只接受空骆驼（尸壳用），否则接受空骆驼或「1 名尸壳乘客」
- 座位语义：`getPassengers()` index 0 = 前座（矛）、>0 = 后座（弓）
- 前座尸壳阵亡 → `onLivingDeath` 里 `stopRiding` 让位，焦骸补前排并换矛
- **旧存档兼容**：`tryAutoMount(level, mob, day, allowHorseSpawn)` 读档时仍执行骆驼匹配（`allowHorseSpawn=false`，不生成新马）；新增 `onCamelJoin` + `MobMounts.tryFillCamel`，骆驼载入时反向找附近骑手补座（空骆驼→尸壳优先、其次焦骸；有尸壳→补焦骸；只有焦骸→尸壳坐前排、焦骸退后座）

## 指令改为 Xd 形式

- `DayCommand` 结构：`/undeadinvasion get | set <Xd> | add <Xd>`（add 仅接受正整数，负数报错；回退用 set）
- 参数使用原版 `StringArgumentType.word()` + 手写 `parseDay()`；**不要用自定义 ArgumentType** —— 教训见下条
- 参数为自由输入，不提供固定补全（曾误加 10d/20d/30d 建议，看起来像固定枚举，已移除）；任意数字如 `47d` 均可
- 参数读取用 `StringArgumentType.getString(ctx, name)`，`DayCounterData` 保留 `setDay/addDays`

### 严重教训：「无效的玩家数据」= 自定义参数类型未注册

- 曾用自定义 `ArgumentType<Long>`（DayArgument）解析 `20d`，未注册到 `ArgumentTypeInfos` / `COMMAND_ARGUMENT_TYPE`
- 后果：服务端每次给客户端发命令树时 `ArgumentTypeInfos.byClass` 抛 `IllegalArgumentException`，异常冒泡到 `PrepareSpawnTask.spawnPlayer`，玩家被 `ServerConfigurationPacketListenerImpl` 以 `multiplayer.disconnect.invalid_player_data`（无效的玩家数据）踢出
- 该异常在日志里表现为 `Couldn't place player in world` ＋ `Unrecognized argument type ...` 堆栈
- 结论：自定义 Brigadier 参数必须 `DeferredRegister.create(Registries.COMMAND_ARGUMENT_TYPE, MOD_ID)` + `ArgumentTypeInfos.registerByClass(...)`；本项目改为只用原版参数类型规避
- 另：`DayCounterEvents.onPlayerLoggedIn` 已加 try/catch，避免同步失败把玩家踢出（该事件内任何异常都会导致同样的断开）

## 修复：一匹坐骑坐两个骑手

- 原因：`MobMounts.tryMount` 里 `addFreshEntity(mount)` 会同步触发坐骑的 `EntityJoinLevelEvent`，其中的 `tryFillMount` 立刻拉了附近一个亡灵上马；随后调用方又让自己指定的骑手 `startRiding`，因 `startRiding(force=true)` 不检查座位数，导致两个乘客
- 修复：新增「预定」标记 `undeadinvasion:mount_reserved`；新建坐骑在 `addFreshEntity` 前打标，指定骑手入座后清除；`tryFillMount` 遇到预定/已载人直接返回；骑手侧三条分支再加 `!isVehicle() && !isReserved()` 即时校验

## 修复：举盾不能即时格挡

- 根因：原版盾牌的 `blocks_attacks` 组件带 `blockDelaySeconds=0.25`（5 tick），`LivingEntity#getItemBlockingWith()` 要求 `elapsedTicks >= blockDelayTicks` 才返回盾牌；AI 只在箭进入 8 格时举盾，箭约 2–3 tick 就命中，永远赶不上
- 修复：`MobBackpack#makeShieldFast` 复制原组件其余字段、只把 `blockDelaySeconds` 改成 0；`createShield()` 用于新建盾牌，`sync` 开头修正旧盾牌
- 同时把 `ShieldBlockGoal` 扫描半径 8 → 16 格（约提前 5 tick 预警）
